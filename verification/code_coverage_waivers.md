# Code coverage waivers

These waivers apply to the Questa code-coverage report for the supported
SHA-256 verification configuration. They document bins that the legal
interface scenarios cannot reach; they do not change RTL or mask functional
coverage.

| Coverage item | Waiver rationale |
| --- | --- |
| Toggle, `u_block_buffer.total_words[63:59]` and `word_cnt[63:16]` (106 bins in merged seed-1 report) | Directed complete messages of 16,384, 65,536, 262,144, and 1,048,576 bits toggle `word_cnt[8:15]`, covering 16 transitions that were previously missing. At the new 1,048,576-bit maximum (32,768 input words), `word_cnt[16:63]` and `total_words[59:63]` remain unchanged. Retain the counter width required by the 64-bit message-length interface and waive the unreachable high-bit toggles. |
| Toggle, controller `error_r` / `o_error` and `sha_top.ctrl_error` / `sha_top.o_error` (8 bins) | The regression drives legal starts only. Error is reserved for a start presented while the controller is not ready; legal tests therefore leave the error outputs low, consistent with `p_no_error`. If illegal-start handling becomes part of the requirements, add directed tests and remove this waiver. |
| Branch, condition, and statement, `sha256_controller.sv:210-211` (`i_start && ~o_ready`) (1 branch, 2 condition outcomes, 1 statement) | Such a start violates the interface contract, is prohibited by `p_start_only_when_idle_ready`, and is never generated by the driver. Keep the defensive error latch; waive the illegal protocol outcome unless illegal-start recovery becomes a required scenario. |
| FSM, block buffer `PADDING -> IDLE` | The ordinary `PADDING` exit is `PADDING -> DONE`; reset is the only route to `IDLE`. The reset-injection test now asserts synchronous reset while the FSM is still in `PADDING`, so this transition is exercised rather than waived. |
| Branch/statement, default arms in `block_buffer_512.sv`, `message_schedule_generator.sv`, and `compression.sv` (3 branches, 4 statements) | Each state enum encodes exactly the listed states (including all encodings for the enum width). A default arm can only execute for an illegal/unknown state, which is outside legal RTL operation. Keep defensive recovery behavior; exclude these default arms in the coverage tool or record this rationale in the waiver database. |
| Expression, `sha256_controller.sv` `bb_done` terms at lines 214 and 233 | The controller enters `INIT` from `WAIT_BLOCK` only after `bb_done` is high. The block buffer holds `DONE` until `CHECK_NEXT` acknowledges it, so `bb_done` remains high through the `INIT` cycle. The false `bb_done` outcome in these expressions is unreachable in the legal protocol. |

Do not use these waivers to claim full code coverage. Report the exclusions
alongside the raw code-coverage result and revisit them when interface limits
or error-handling requirements change.
